# 电影便当

> 把一万三千部电影做成一家「精神食粮」餐馆:爱情片叫马卡龙,恐怖片叫河豚,短片叫「一口」,三小时史诗叫「满汉全席」。你在聊天里跟 AI 说一句"今晚想吃点酸的韩餐,别太长",他去厨房翻,端回来三份便当卡。看完打一张小票收进册子。

这是一份可以照着做的教程。核心不是代码量(总共八百来行),而是三个想法:

1. **把冷冰冰的元数据翻译成有温度的语言** —— 「悬疑 / 韩国 / 120分钟 / 7.2分」变成「螃蟹 · 韩餐 · 正餐」。同一份数据,后者会让人想点开。
2. **推荐的入口是聊天,不是页面** —— 页面是货架和账本,主入口永远是"跟他说一句话"。
3. **看过的片子要留下一件东西** —— 一张能存成图片的小票,比一个"已看"的勾更值得回头翻。

技术上依赖一个 API:**TMDB**(themoviedb.org),个人使用免费、无有效期、中文片名和简介齐全、自带海报。

---

## 零、成品长什么样

三个页签:

- **便当** —— 「今日便当」盲盒(点盒盖 → 打包动画 → 随机一份没看过的);「食单」(想看的);「看过」
- **货架** —— 五排维度筛选(菜系 / 菜色 / 分量 / 熟成度 / 店铺)+ 排序 + 搜索,一页 30 部翻页
- **小票** —— 每看完一部生成一张热敏纸小票,可存成图片

外加**聊天里的主厨**:AI 拿着一个工具去片库翻,回复里会长出便当卡。

数据规模参考(作者的库):13,549 部,17 个菜系,其中 99.9% 有中文简介。

## 一、拿钥匙:TMDB API Key

1. 打开 themoviedb.org 注册(邮箱验证一下)
2. 头像 → **设置(Settings)** → 左侧 **API**
3. 申请密钥,类型选 **Developer**,表格随便填合理内容(个人开发者秒批)
4. 页面给两串东西,取 **API Key (v3 auth)** 那串 32 位的

没有有效期,也没有月度配额,只有速率限制(每秒 50 次左右)。进货脚本控制在每秒 30 次就相安无事。

Key 存进项目根目录的 `.env`:

```
TMDB_API_KEY=你的32位key
```

命名的诀窍:**别找形似,找"吃它时的感受"**。河豚配恐怖,是因为有毒还让人上瘾;压缩饼干配战争,是因为难以下咽但你会记住;茶泡饭配文艺剧情,是因为清淡、慢、要有耐心。

### 分量(按片长)

一口(<40分钟)· 小食(40–80)· 正餐(80–130)· 大份(130–180)· 满汉全席(180+)

### 熟成度(按年份)

刚出锅(近三年)· 温热(2010年代)· 常温(90–00年代)· 陈酿(70–80年代)· 老坛(更早)

### 店铺(按热度和口碑的交叉)

- **当红**:2023 年后 + 评分人数 ≥500
- **老字号**:评分人数 ≥3000 且分数 ≥7.0(经典)
- **隐藏菜单**:评分人数 <1000 但分数 ≥7.2(遗珠 —— 整个项目最有价值的一档)
- **家常**:其余

> ⚠️ 顺序有讲究:**先判年份再判人数**。否则 2026 年的新片会因为人多分高被打成「老字号」,看着很怪。作者踩过这个坑。

### 菜系(按出品国)

中餐 / 港片 / 日料 / 韩餐 / 美餐 / 法餐 / 意餐 / 英餐 / 泰餐 / 印度菜 / 伊朗菜 / 俄餐 / 德餐 / 西班牙菜 / 拉美菜 / 北欧菜。

港片单独立户 —— 味道和内地不同,值得一个自己的格子。伊朗菜也留着,文艺片重镇。

## 三、进货:一晚上装满一万三千部

TMDB 的 `discover` 接口就是天然的多维筛子。关键设计是**分三波扫**,因为单一条件永远扫不出"既有经典又有遗珠"的库:

```python
DECADES = [(1900,1969),(1970,1989),(1990,1999),(2000,2009),(2010,2016),(2017,2021),(2022,2026)]

def plans():
    # 波1 老字号: 全球, 人数>=1000, 分>=6, 按年代分片
    for a, b in DECADES:
        yield ('老字号', {'vote_count.gte': 1000, 'vote_average.gte': 6.0,
                        'primary_release_date.gte': f'{a}-01-01',
                        'primary_release_date.lte': f'{b}-12-31',
                        'sort_by': 'vote_count.desc'})
    # 波2 隐藏菜单: 按国家×年代, 人数 60-999, 分>=6.8  ← 遗珠都在这一波
    for c in COUNTRIES:
        for a, b in DECADES:
            yield ('隐藏菜单', {'with_origin_country': c, 'vote_count.gte': 60,
                             'vote_count.lte': 999, 'vote_average.gte': 6.8, ...})
    # 波3 一口: 短片, with_runtime.lte=40
    for a, b in DECADES:
        yield ('一口', {'with_runtime.lte': 40, 'vote_count.gte': 25, ...})
```

**为什么要按年代和国家切片**:TMDB 的 discover 每个查询最多返回 500 页。不切片的话,一个"全球高分片"查询会被截断在前一万部,全是好莱坞。按 `国家 × 年代` 切成一百多个小查询,每个都能扫到底,冷门国家的片才浮得上来。

扫描阶段只拿 id(去重后一万三千个),再逐部拉详情补齐时长、出品国、关键词:

```python
d = await get(cli, f'/movie/{i}', append_to_response='keywords')
# 中文简介缺失时回退英文
if d and not (d.get('overview') or '').strip():
    en = await get(cli, f'/movie/{i}', language='en-US')
    if en: d['overview'] = en.get('overview') or ''
```

限速用一个简单的令牌桶(每秒 30 次)+ 8 个并发,一万三千部详情大约九分钟拉完。整个进货 **11 分钟**,数据落 SQLite。

派生字段(菜系、菜色、分量、档位、熟成度)在**入库时算好存进列**,不要查询时现算 —— 筛选要走索引。

## 四、后端:七个接口就够了

一张主表 `films` + 两张小表 `bento_wish`(想看)和 `bento_log`(小票)。

```
GET  /api/bento/facets            各维度的取值和数量(前端画筛选栏)
GET  /api/bento/search            搜索/筛选/翻页
GET  /api/bento/random            盲盒(自动排除吃过的)
GET  /api/bento/film/{id}         详情
POST /api/bento/wish              加/移出食单
POST /api/bento/log               打小票
GET  /api/bento/poster/{size}/{p} 海报代理
```

三个值得说的细节:

### 1. 海报要自己代理,不要让手机直连 TMDB 图床

```python
@router.get('/api/bento/poster/{size}/{path}')
async def poster(size: str, path: str):
    f = POSTER_DIR / f'{size}_{path}'
    if not f.exists():
        r = await cli.get(f'https://image.tmdb.org/t/p/{size}/{path}')
        f.write_bytes(r.content)
    return FileResponse(f, headers={'Cache-Control': 'public, max-age=2592000, immutable'})
```

一是国内直连图床不稳,二是缓存在自己服务器上第二次就是本地读盘。作者的库跑了几天,缓存了 297 张海报占 6.8 MB —— 只缓存你真正看过的,不用预热。

### 2. 搜索要让"片名精确命中"排在前面

按人气排序时,搜 "possession" 会让《招魂》这种人气高的片排在真正叫 *Possession* 的片前面。加一层排序前缀:

```python
if q.strip():
    ql = q.strip().lower().replace("'", "''")   # ← 别忘了转义单引号, 否则 Ocean's Eleven 会炸
    order = (f"(lower(title)='{ql}' OR lower(title_orig)='{ql}') DESC, "
             f"(lower(title) LIKE '{ql}%' OR lower(title_orig) LIKE '{ql}%') DESC, ") + order
```

### 3. 本地搜不到就现拉 TMDB 补货

库再大也有漏网的。搜索结果少于 3 条时,自动去 TMDB 搜一次并入库,用户无感:

```python
if q.strip() and total < 3 and page == 1:
    await tmdb_search_and_add(q.strip())   # 拉回来的片打上 waves=["现拉"] 标记
```

## 五、主厨:让 AI 用一个工具点菜

**这是整个项目最值得抄的一段。** 不要做成"点进页面 → 摇骰子 → 出结果"的算命摊,要做成"你在饭桌上说一句话,他起身去厨房"。

给 AI **一个**工具(不是七个 —— 工具说明书每轮都占上下文,能合就合),用 `action` 区分动作:

```json
{
  "name": "bento",
  "description": "电影便当厨房。action=pick 按她的口味挑1-3部; search 按片名/维度找;
                  random 盲盒; detail 详情; wish 记食单; log 打小票; wishlist; history。
                  菜色dish: 马卡龙(爱情)/河豚(恐怖)/螃蟹(悬疑)/炸鸡(喜剧)/...
                  分量portion: 一口/小食/正餐/大份/满汉全席
                  返回的 [bento:...] 标记原样放进正文会渲染成便当卡。",
  "parameters": { "action": {...}, "cuisine": {...}, "dish": {...}, "portion": {...} }
}
```

两个关键点:

**① 把菜单写进工具描述里。** AI 不需要额外的提示词就知道"酸的韩餐"该怎么翻译成参数 —— 描述里写了 `马卡龙(爱情)` 这样的对照,它自己会连。

**② 用标记回传卡片,而不是让 AI 复述。** 工具返回值里带一行:

```
[bento:496243:寄生虫:2019:/7IiTTgloJzvGI1TAYymCfbfl3vT.jpg|韩餐·卤煮/生鱼片·正餐·8.5分]
```

并在返回文本里告诉 AI:"把要推荐的那几条标记**原样**放进正文"。前端渲染消息时把这个标记替换成卡片元素:

```javascript
src = src.replace(/\[bento:(\d+):([^\[\]:|]*?):(\d{0,4}):([^\[\]|]*?)\|([^\]]*)\]/g,
  (_a, id, title, year, poster, meta) => {
    cards.push({id, title, year, poster, meta});
    return '<div class="bento-card-slot" data-i="' + (cards.length-1) + '"></div>';
  });
```

好处是 AI 不用在回复里手打片名、年份、海报地址(会打错),它只负责**挑**和**说为什么**,数据由标记保真带过来。这个模式可以复用到任何"AI 推荐 + 卡片展示"的场景。

## 六、前端的三个小心思

### 盲盒:让加载动画自己走完

```javascript
const t0 = Date.now();
const r = await api('/api/bento/random?n=1');
await new Promise(res => setTimeout(res, Math.max(0, 900 - (Date.now() - t0))));
```

接口 50 毫秒就返回了,但那样"打包便当"的动画一闪而过,像什么都没发生。**强制留够 900 毫秒**,期待感才成立。动画本身是四个陶土色小方块轮流起伏(CSS `@keyframes` 十行),不用引任何动画库 —— 自己画的反而和整页一个质地。

### 结果长在盒盖上

第一版做成"点盒盖 → 结果出现在盒盖下方",盒盖点完就成了废件。改成**结果直接替换盒盖内容**,右上角加一枚 ↻ 再来一份。同样的面积,信息密度翻倍。

### 筛选栏默认收起

五排维度铺开会把列表挤到屏幕外。收成一行摘要「挑菜 · 日料 · 河豚 · 高分」,点开才展开。每个维度值旁边配一行小注(`河豚 恐怖`、`一口 40分钟内`、`隐藏菜单 人少分高`)—— 自创的黑话必须给注解,否则只有你自己看得懂。

## 七、小票:让"看过"变成一件东西

结构照抄"上图下文"的文字卡片:顶部横裁一张剧照(海报裁不全没关系,反而有电影感),下面是等宽字体的热敏纸区域。

字段:

```
        猫窝影厅 · 票号 20260908-003
              异 教 徒
         The Wicker Man · 1973
- - - - - - - - - - - - - - - - - -
分量        正餐 · 93 分钟
菜系        英餐 · 河豚/茶泡饭
场次        2026-09-08 · 影院
座位        沙发 A1 · A2
心情        好奇 → 发毛
  | Reasonable people don't dance...
- - - - - - - - - - - - - - - - - -
她  这片最后十分钟让我坐直了
他  一整部片都在铺一个笑着的陷阱
她  4 星      他  5 星
|||| | ||| || |   [猫爪 · 已验票]
```

**存成图片**用 html2canvas,一行调用,存下来就是可以直接发社交媒体的素材:

```javascript
const cv = await html2canvas(el, {useCORS: true, scale: 2, backgroundColor: '#fff'});
const a = document.createElement('a');
a.download = '便当小票.png'; a.href = cv.toDataURL('image/png'); a.click();
```

小细节:导出前把"存成图片"按钮本身 `visibility: hidden`,否则按钮会印在图里。

## 八、视觉:一个元素做大做淡

整页只用两个装饰元素:**猫爪**和**四角星**,都是手写 SVG。

- 四角星当评分符号(五颗,按 TMDB 的十分制折半)
- 猫爪只做一件事:**盖在看过的片子上**当验票章。不参与评分,不当图标用。
- 详情页右上角放一枚**放大到 190px、透明度 11% 的猫爪**,一半切出画面

最后这条是整套视觉里最有效的一招:**一个元素做大、做淡、切出画面**,比满屏小图标高级得多。

配色只有五个变量:

```css
--bg:#f6f3ee    /* 奶油底 */
--sf:#fffdf9    /* 卡片 */
--ink:#201f1d   /* 墨 */
--mut:#8a8378   /* 次要文字 */
--ac:#c8755a    /* 陶土色, 唯一的强调色 */
```

图标一律用线条 SVG,不用 emoji —— emoji 在不同设备上长得不一样,而且会把精心调的灰度体系打乱。

## 十、可以往哪儿长

- **口味维度**(甜/咸/酸/苦/辣/鲜/淡):TMDB 没有现成标签,要拿"类型 + 关键词 + 简介"喂给一个便宜的文本模型批量打标。几千次调用不贵,但要设计好提示词,不然全被打成"咸"。
- **营养报告**:本月吃了几份、菜系饼图、"蛋白质(动作片)摄入不足,建议补充铁板烧"——用营养师的口吻胡说八道,是这个隐喻最好玩的地方。
- **忌口**:不吃血腥 / 不吃虐 / 不吃超过两小时,存成口味档案,所有推荐自动避开。
- **豆瓣分**:豆瓣没有公开 API 且反爬极凶,海外服务器基本别想。真要的话小批量走国内出口补。

## 附:两个坑

**坑一 · 档位判断顺序。** 前面说过,先判年份再判人数,否则新片会被打成老字号。

**坑二 · SQL 里的单引号。** 拼排序前缀时片名带撇号(*Ocean's Eleven*)会把语句撑炸。`.replace("'", "''")`,别问怎么发现的。

---

*做这个的起因是一本叫《电影药丸》的小册子 —— 按"病症"推荐电影,书页底下留着「治疗日期」和「治疗体验」两个空格。药是治病的,便当是过日子的;那两个空格,就是后来的小票。*
